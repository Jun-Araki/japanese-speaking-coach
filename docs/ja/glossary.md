# ユビキタス言語定義

**この文書は日本語版が正。** 変更したら [`../en/glossary.md`](../en/glossary.md) も更新する。

これはコードの説明書ではない。**評価データ120件のラベル付け基準であり、README に載せるすべての数字の定義である。**

ラベル付けを始めたあとに定義がぶれると、それ以前にラベルを付けた件が不整合になり、評価全体が無価値になる。**この文書は意図的にしか変更せず、変更したらラベル済みの件を必ず見直す。**

---

## 1. 中核となるドメイン用語

| 用語 | 英語 | 定義 | コード上の識別子 |
|---|---|---|---|
| **場面** | Scene | 学習者が練習する状況。固定リスト、§3 参照 | `scene` |
| **レベル** | Level | 学習者が申告した習熟段階。固定リスト、§4 参照 | `level` |
| **ターン** | Turn | 学習者の発話1つと、それに対する AI の返答1つ | `turn` |
| **会話セッション** | Session | 「会話を始める」から「会話を終える」までの全体 | `session` |
| **振り返り** | Review | セッション終了後に表示される、訂正の一覧画面 | `review` |
| **訂正** | Correction | 学習者の1文に対する判断。直すべきか、直すならどう直すか | `correction` |
| **自然な言い方** | Natural phrasing | その場面でネイティブが使う、直した後の文 | `corrected_sentence` |
| **理由** | Reason | 訂正の理由を英語で1〜2文 | `reason_en` |
| **根拠** | Grounding | 理由の裏付けとして引用した文法リファレンス | `grounding_ids` |
| **もう一度** | Say again | 音声認識が誤ったときの録音し直し。**打ち直しではない** | `say_again_count` |

**コードにも画面にも、次の語を同義語として使わない**：feedback / suggestion / fix / error / mistake。上記の各概念に対応する語はそれぞれ1つだけ。

## 2. ラベル付けの判断 — 最も重要な定義

評価データの各件と、モデルの各出力は、**2値のラベルを1つだけ**持つ。

### `needs_correction: true`（NG）

その場面で日本人に対して言う前に、直したほうがよい文。

次の場合に `true` を付ける。

- **文法的に誤っている** — 助詞の誤り、活用の誤り、必須要素の欠落
- **場面に対して丁寧さが合っていない** — 目上に普通形、友人に硬い敬語
- **文法的には正しいが、ネイティブはそう言わない** — 不自然な語の組み合わせ、英語からの直訳
- **存在しない定型句** — 決まった挨拶を勝手に変形したもの

### `needs_correction: false`（OK）

その場面でネイティブがそのまま受け入れる文には `false` を付ける。**より上品な言い方が存在してもよい。** こちらのほうが判断が難しく、そして重要である。この30件は**余計な直しを測るためだけに存在する**。

次は明示的に `false` とする。

- **簡単だが正しい文。** 初級者の文は、素朴であることを理由に誤りとしない
- **実際に使われている**地域差・くだけた言い方
- **ネイティブが特に気に留めない文。** 自分が個人的に別の言い方を好むかどうかは関係ない

### 丁寧さの下限 — 相手で決まる（2026-08-05 決定）

「**場面に対して丁寧さが合っていない**」を判断するには、**どこまでくだけてよいかが決まっていなければならない。** 決まっていないと、同じ普通形の文が `true` にも `false` にもなり、`detection_accuracy` と `over_correction_rate` は**どちらに倒したかの数字**になる。ラベル付けの初日に候補60件が実際にこの揺れを起こしたので固定した。

**決めているのは場面ではなく相手である。** 同じ「トイレはどこ？」でも、同僚に言うなら問題なく、店員に言うなら直す。

| 段階 | 相手 | 下限 | 該当する `scene` |
|---|---|---|---|
| **A** | 近所の人・同僚 | 丁寧語は要らない | `greeting` `thanks` |
| **B** | 初対面の相手・店員 | **お／ください／です／ます のどれか1つは要る** | `self_introduction` `simple_request` |
| **C** | 待たせている同僚・上司 | **です・ます が要る** | `delay_notice` `workplace_keigo` |

- **B の下限は「丁寧語の要素が1つ」であって、文全体を丁寧形にすることではない。** 「これ、ください」「お名前は」は下限を満たすので `false`。「トイレはどこ？」「名前は？」は1つも無いので `true`
- **C で普通形が `true` になるのは §3 のとおり**、丁寧さの制御が実際に必要になる場面だからである
- **A では、丁寧さだけを理由に `true` を付けない。** `true` は**文法の誤り／ネイティブが言わない言い方／定型句の変形**の3つからのみ付ける
- **向きを誤った定型句は、丁寧さではなく定型句の誤用として `true`。** 「ご苦労さまです」を目上に言う類は A でも `true` になる
- **C が求めているのは です・ます であって、尊敬語・謙譲語の完備ではない。** 「少し考えます」は上司に対しても `false`
- **「あなた」を理由に `true` を付けない**（2026-08-05 検証で決定）。不自然に見えるのはたいてい語順か直訳のほうで、そちらを理由にする。「あなたはこの本を持っていますか」は `false`

### 迷ったときの規則

**迷ったら `false` を付け、迷った理由をメモに残す。** このシステムは「直しすぎるより直さない」側に倒す設計であり、誤って `true` を付けた件は**余計な直しを静かに正解として報酬づけてしまう**。第二の採点者に説明できないラベルの件は、そもそも作らない。

### ラベルに含めないもの

- **誤りの種類は記録しない。** 助詞／活用／語彙のような分類はしない。初級者には不要で、ラベル付けと採点を重くするだけで得るものがない
- **発音は判定しない。** 音声はあくまで入力手段である

## 3. 場面

やさしい順。初級者が後半まで到達することは想定しない。

| `scene` | 日本語 | 備考 |
|---|---|---|
| `greeting` | 挨拶 | 入口。全員がここから始める |
| `self_introduction` | 自己紹介 | 名前、仕事、出身 |
| `thanks` | お礼 | |
| `simple_request` | 簡単な依頼 | |
| `delay_notice` | 予定と遅れの連絡 | 丁寧さの制御が実際に必要になる最初の場面 |
| `workplace_keigo` | 職場の敬語 | 上限。日印の橋渡しの実体験が接続する場所 |

**学習者には必ず自分の言葉で話させる。** やさしくしてよいのは**場面**であって、学習者が作る文を選択式にはしない。定型句から選ばせると**直す対象が消え、評価が成立しなくなる**——それはこのプロジェクトの中身そのものを失うことを意味する。

## 4. レベル

| `level` | 画面に出す表記 | おおよその対応 |
|---|---|---|
| `beginner` | Beginner | 日本語能力試験 N5 |
| `upper_beginner` | Upper beginner | 日本語能力試験 N4 |
| `intermediate` | Intermediate | 日本語能力試験 N3 |

**「おおよその対応」という表現は意図的である。** 日本語能力試験の過去問と市販教科書は取り込まない。難易度の段階は SudachiDict の語の頻度から導くので、対応はあくまで近似であり、README にもそう書く。

**レベル超過語**（`over_level_word`）：**AI の返答**に含まれる語のうち、頻度の段階が学習者の申告レベルを超えているもの。SudachiPy で分かち書きして検出する——日本語は文字列の一致だけでは語の境界が分からないため、**形態素解析が飾りではなく必然として必要になる。**

## 5. 指標の定義

訂正に関する指標はすべて、評価データを**テキストのまま訂正エンジンに直接渡して**測る。アプリもマイクも音声認識も経由しない。

| 指標 | `識別子` | 定義 | 8月の目標 |
|---|---|---|---|
| 判定の正しさ | `detection_accuracy` | `true` とラベル付けした90件のうち、システムも `true` と判定した割合 | 85%以上 |
| **余計な直しの率** | `over_correction_rate` | `false` とラベル付けした30件のうち、システムが誤って `true` と判定した割合。**低いほど良い** | 15%以下 |
| 直しと理由の妥当性 | `correction_validity` | 40件を §6 の3段階で人手採点 | 妥当85%以上 |
| 採点者の一致率 | `rater_agreement` | 本人と第二の日本語ネイティブの両方が採点した20件のうち、評価が一致した割合 | 80%以上 |
| 検索の当たり率 | `retrieval_hit_rate` | 学習者の文に対し、根拠として妥当な解説が上位3件に入った割合 | 80%以上 |
| レベル遵守率 | `level_compliance_rate` | AI の返答のうち、レベル超過語が閾値を超えなかった割合 | 90%以上 |
| 書式適合率 | `format_compliance_rate` | 出力が壊れていない JSON であり、**かつ**理由が英語で返った割合。**精度とは別に記録する**ので、言語の取り違えを推論の誤りと混同しない | — |
| 応答時間 | `latency_ms` | 中央値と95パーセンタイル。**音声段の有無で分けて記録する** | 改善前後を比較 |
| 利用 | — | 1回以上会話したテスターの人数と、1人あたりのターン数 | 5人以上 |

**直した文は完全一致で採点しない。** 自然な言い方は1つに決まらないため、完全一致で測ると実力よりはるかに低く出る。機械採点するのは2値のラベルだけで、言い方と理由の質は目視で判断する（§6）。

**公開するすべての数字に `n` と誤差の目安を併記する** — 例：「92%（n=40、目安の誤差 ±8pt）」。評価用40件では誤差はおよそ ±8ポイントであり、**それを自分から書くほうが、大きい数字を出すより信頼を得る。**

## 6. 直しと理由の妥当性 — 採点尺度

40件を人手で採点する。うち20件は第二の日本語ネイティブが独立に採点する。

| 評価 | 意味 |
|---|---|
| **妥当** | 直した文はネイティブが実際に言う言い方であり、英語の理由も正確で初級者の役に立つ |
| **不十分** | 訂正自体は受け入れられるが、理由が曖昧・一般論的で、実際の問題点を説明していない |
| **誤り** | 直した文が不自然、または意味が変わっている。あるいは理由が事実として誤っている |

`correction_validity` は**妥当**のみを数える。

## 7. 評価プロセスの用語

| 用語 | 定義 |
|---|---|
| **開発用（`dev`）** | 80件。プロンプトと閾値の調整はこちらだけを見て自由に行う |
| **評価用（`test`）** | 40件。8月の最初と最後にしか触らない。ここを見て調整すると**すべての数字が自己採点になり無価値になる** |
| **ベースライン（`baseline`）** | 素朴な実装。「この日本語を直して、理由を教えて」と大規模モデルに1回投げるだけ。**本実装が存在する前に測る**ので、比較表が正直なものになる |
| **実行記録（`run_record`）** | 測定のたびに書き出す JSON。モデル名・プロンプトの版・日付・データ分割・**件数（`n`）**。README の数字にはどの実行のものかを書く。**`n` が無いと、README のある数字がどの規模の測定なのかを後から復元できない**（§5 はすべての公開数字に `n` の併記を求めている） |
| **書き換えすぎ** | 元の文からの編集距離が閾値を超えた「訂正」。それは訂正ではなく別の文なので、検証ノードが捨てる |
| **改善サイクル** | 「数字を測った → 具体的に何かを変えた → もう一度測った」の1周を記録したもの。README に最低1周は必要 |

### 閾値

値と根拠は [`config/thresholds.toml`](../../config/thresholds.toml) にある。**コードに直値を埋め込まない。** 現状は次のとおり。

| 閾値 | 暫定値 | 状態 |
|---|---|---|
| 書き換えすぎ：正規化編集距離 | `0.65` | 暫定 — 第2週に開発用データで確定 |
| 書き換えすぎ：短文の絶対距離 | 8文字未満に対して `6` | 暫定 |
| レベル超過の内容語比率 | `0.2` | 暫定 |
| 無条件で弾く段階差 | `2` 段階 | 暫定 |
| 1返答あたりの再生成回数 | `1` | 確定 — 無制限だと会話が止まるため |

**注意が必要なのは書き換えすぎの閾値である。** 丁寧形への訂正は、短い文に長い固定語尾を足すため、正規化した比率では高い値になる。**しかもそれは、このアプリが出す訂正のうち最も頻出で、最も明白に正しい種類である。** 2026-08-02 に実測した値：

| 元の文 | 直した文 | 正規化編集距離 |
|---|---|---|
| ありがとう | ありがとうございます | **0.50** |
| おはようです | おはようございます | 0.44 |
| 明日行くです | 明日行きます | 0.33 |

**多くの人が最初に選ぶであろう 0.5 を閾値にすると、`ありがとう → ありがとうございます` が黙って捨てられる。** 捨てられた正しい訂正は**学習者にも届かず、指標にも現れない**ので、意識して探さない限り気づけない。第2週に、開発用データの正しい訂正が何件この閾値で捨てられるかを必ず数えること。
