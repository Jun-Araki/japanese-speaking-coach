## プロバイダの選定（2026-08-03）

**当初は Claude API を選んでいたが、Anthropic の決済フォームが通らずキーを取得できなかった。**
`GEMINI_API_KEY` は既に手元にあるため、**Gemini に切り替えて着手を優先した。**

- **LangChain 経由で呼ぶので、提供元の差し替えは1行で済む。** Anthropic の課金が解決したら戻せる
- **ベースラインと本実装は必ず同じモデルで測る。** 素朴版と本実装を別のモデルで測ると、
  比較表が「検証ノードの効果」ではなく「モデルの違い」を見ていることになり、**評価の主役が壊れる**
- 差し替えた場合は、**両方を測り直す**か、実行記録（`run_record`）でモデルを明示して読者が区別できるようにする

## 保存しないという決定（2026-08-16）

**当初は同意記録と利用ログを無料枠の PostgreSQL（Neon か Supabase）に書く計画だった。やめた。**

- **利用者が2〜3人しかいない。** その規模の利用ログから統計として言えることは何もない
- **学習者の発話は個人情報である。** 得るものが無いのに保存の責任だけを負うのは割に合わない
- **保存しないので同意記録も要らなくなる。** 注意書きは残す（音声が外部 API に送られるのは事実であるため）
- **依存が1つ減り、デプロイが短くなる**

**この判断は README に1行書く。** 「無料 DB を繋げなかった」ではなく
**「保存先を検討した結果、保存しないことを選んだ」**が事実であり、後者のほうが説明として筋が通る。

**代償**：応答時間・「もう一度」の押下回数・継続率が測れなくなる。**そして最大の代償は、
音声認識の精度と通しの精度が測れなくなること**である（録音が残らないので耳で書き起こす材料が無い）。
**いずれも指標から降ろした**
（[product-requirements.md](product-requirements.md) の「測らないと決めたもの」参照）。

## 音声の提供元

**9月上旬、音声を作るときに決める。** Gemini は音声認識・音声合成の両方に対応しており
（WAV 可、日本語対応）、キーが1本で済む利点がある。ただし **Gemini の音声認識はプロンプト経由
＝言語モデルが書き起こす**ため、**学習者の言い間違いを勝手に直してしまう度合いが、専用の
音声認識モデルより強い可能性がある**。これは本アプリの中身を消しかねない。

**ただしこれは実測ではなく理屈で決めるしかない（2026-08-16 改訂）。** 旧版は「評価は2段階に分けて測る」
の枠で両者を実測して決めるとしていたが、**音声を保存しないと決めたのでその比較は走らせられない**。
したがって上の理屈にもとづいて**専用の音声認識モデルに寄せる**判断をし、
**README には「この選定は測っていない」と書く。**

> **2026-08-20 に決着した。`OPENAI_API_KEY` が取得できていなかったため Gemini で実装し、
> 上の懸念が実測で再現した。** 下節を参照。

## 音声認識が学習者の誤りを消す（2026-08-20 実測）

**上の懸念はそのとおりだった。** `dev` の実際の誤り5件を合成音声にして書き起こしたところ、
**誤りが保たれたのは 1/5**。「オフィス**で**います」→「オフィス**に**います」、
「毎日**で**走る」→「毎日走る」のように、**助詞や活用の誤りが黙って直された。**
正しい日本語5文では実質の誤りは固有名詞1件だけで、**正しく聞こえる音は正確に、
正しくない音は「直して」書き起こす。** 言語モデルが書き起こしている以上そうなる。

**書き起こしプロンプトの厳格化では防げなかった**（「学習者である」「文法を直すな」
「不自然でもそのまま書け」と明示しても 1/5 のまま。保たれる項目が入れ替わっただけ）。

**Gemini の他モデルも試した（2026-08-20）。同じ合成音声を4モデルに聞かせた。**

| モデル | 誤りを保った |
|---|---|
| `gemini-2.5-flash`（採用中） | 1/5 |
| `gemini-2.5-pro` | 測定不能（HTTP エラー） |
| `gemini-3.5-flash` | 1/5 |
| `gemini-3.7-flash` | 1/5 |

**新しいモデルほど流暢に直す。** `3.5` と `3.7` は「払うたいです」を**きれいに「払いたいです」へ直した**
——書き起こしとしては優秀で、**このアプリにとっては誤りの消去**である。
**したがって Gemini の中に打ち手は無い。**

**同じ音声・`temperature: 0` でも結果が揺れる**（`2.5-flash` は2回の測定で
「私はオフィスにいます」と「私はオフィスいます」を返した）。**1/5 という数字自体に幅がある。**

**この測定は合成音声を使っているので、崩れたのが合成側か認識側かを分離できない。**
分離には実際の学習者の録音が要り、**本アプリは音声を保存しない**——
上で「実測では決められない」と書いたのと同じ制約である。

**したがって現状はこう扱う。**

- **公開しているすべての数字は文字入力で測っている**（訂正エンジンに直接流している）
- **画面のマイクの上に、誤りが消えることがある旨を出す。**
  学習者本人がそれを見抜けない以上、README ではなく画面に出す
- **本命の直しは専用の音声認識に寄せること**（`whisper-1` 等）。**提供元のキーが要る**

## 選定を決めた制約

- **無料のデプロイ先は、再起動後にファイルが残ることを公式に保証していない。** ~~利用ログは外部のデータベースに書く~~ → **何も保存しないと決めたので、この制約は当たらなくなった**（上の「保存しないという決定」）
- **Streamlit は常時つながった通信に向いていない**ため、押さずに話し続ける形は**9/20 までは作らない**。応募開始（9/28）以降に、テスターから実際に「押すのが面倒」という声が出た場合のみ検討する
- **SudachiDict のパッケージは約70MB** ある。Docker のビルド時に入れる前提で書く
- **ローカルモデルは 9/20 まで使わない。** 狙いは大規模モデルを製品に組み込む応用側であり、GPU 代と試行錯誤は**毎日2時間（週14時間）**の予算に入らない
- **Web アプリのみ。モバイルアプリは作らない。** 審査の工数は求人要件と無関係で、インストールを挟むとテスターが激減する
- **UI フレームワークもデザインシステムも導入しない。** 見た目は CSS のみ、1時間で切る

## 作る順番（2026-08-18 改訂）

**縦スライスを先に通す。** まず Streamlit を直結し、テキストだけで会話と訂正を動かして中身を固める（**完了済み**）。

そのあとは**直列に1つずつ**進める。**枠が毎日2時間（週14時間）に戻っても、同時に2つは動かせない。**

1. **評価を閉じる**（〜8/30）— ベースラインとの比較表、RAG、改善サイクル1周
2. **触れる形にする**（〜9/6）— FastAPI へ切り出し、LangGraph で結線、**公開 URL**
3. **音声に載せ替える**（〜9/12）— 録音・文字起こし・音声合成・会話セッション
4. **仕上げる**（〜9/20）— テスターの感想の反映、Docker、README 完成

**旧版は音声を API 化と同時に置いていた。** 直列にしたのは、同時に動かすと**どちらも中途半端なまま
テスターに渡す日（9/13）を迎える**からである。
**②を③より先に置いたのは、触れないものは評価されないため。**

## ライセンス

SudachiPy と SudachiDict は Apache-2.0 で継承条件がないため同梱してよい。README に出典と license を明記する。JMdict と KANJIDIC2 は CC BY-SA なので同梱しない。**市販教科書と日本語能力試験の過去問は取り込まない**——難易度の段階は語の頻度から自作し、「日本語能力試験の水準におおよそ対応」という表現に留める。

**語の頻度は BCCWJ（現代日本語書き言葉均衡コーパス、国立国語研究所）の語彙表から取る（2026-08-11 追記）。** 短単位（DOI 10.15084/00003218）と長単位（DOI 10.15084/00003212）の ver1_0、取得日 2026-08-11。**SudachiDict は頻度を持っていない**（公開されているのは表層・見出し・読み・品詞だけ）ので、分かち書きと頻度で出どころが分かれる。

**BCCWJ は同梱しない。** 「研究・教育目的での利用は無償」とあるだけで**再配布の可否が書かれていない**ため、JMdict と同じ扱い（`.gitignore` ＋ 取得スクリプト）にする。`wordfreq` は**データが CC BY-SA** であることと、**MeCab を要求して形態素解析器が二重になる**ことの2点で採らなかった。
