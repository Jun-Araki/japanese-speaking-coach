# 技術仕様書

**この文書は日本語版が正。** 変更したら [`../en/architecture.md`](../en/architecture.md) も更新する。

> **薄く書く方針。** 下の表が技術選定の公開版である。**8月はこの表以外に手を出さない。**

## 技術スタック

| 領域 | 選定 | 理由 |
|---|---|---|
| 大規模言語モデル | LangChain → Claude API | 日本語の質が高い |
| 音声認識 | OpenAI の transcription エンドポイント | Streamlit が返す WAV をそのまま送れる |
| 音声合成 | OpenAI の speech エンドポイント | 日本語対応・逐次再生対応。**利用規約が「AI が生成した音声だと明示すること」を求めている** |
| 形態素解析 | SudachiPy ＋ SudachiDict（Apache-2.0） | 日本語は語が空白で区切られないため、語彙レベルの判定には形態素解析が要る |
| 埋め込み | sentence-transformers の多言語モデル | 日本語を含む検索 |
| ベクトルデータベース | Chroma | ローカル最速、デモには十分 |
| エージェント | LangGraph | 会話と訂正を並列に走らせ、検証で差し戻す＝グラフで書く必然性がある |
| データベース | PostgreSQL 無料枠（Neon か Supabase） | 同意記録と利用ログ |
| API | FastAPI | `POST /chat` `POST /check` `GET /health` |
| UI | Streamlit | 最速で公開デモに到達できる |
| コンテナ | Docker ＋ compose | `docker compose up` で画面・API・データベースが起動する |
| 評価 | 自作スクリプト（pytest 可） | README の数字を作る |
| デプロイ | 画面＝Streamlit Community Cloud／API＝Hugging Face Spaces（代替 Render） | 無料枠。秘密情報は各サービスの secrets 機能で管理 |

## 選定を決めた制約

- **無料のデプロイ先は、再起動後にファイルが残ることを公式に保証していない。** 利用ログは初日から外部のデータベースに書く。ファイル保存にするとテスターの数字を失う
- **Streamlit は常時つながった通信に向いていない**ため、押さずに話し続ける形は8月には作らない。11月に、テスターから実際に「押すのが面倒」という声が出た場合のみ検討する
- **SudachiDict のパッケージは約70MB** ある。Docker のビルド時に入れる前提で書く
- **8月はローカルモデルを使わない。** 狙いは大規模モデルを製品に組み込む応用側であり、GPU 代と試行錯誤は朝2時間の予算に入らない
- **Web アプリのみ。モバイルアプリは作らない。** 審査の工数は求人要件と無関係で、インストールを挟むとテスターが激減する
- **UI フレームワークもデザインシステムも導入しない。** 見た目は CSS のみ、1時間で切る

## 作る順番

**縦スライスを先に通す。** まず Streamlit を直結し、テキストだけで会話と訂正を動かして中身を固める。**そのあと**音声に載せ替え、FastAPI と LangGraph へ切り出す。

## ライセンス

SudachiPy と SudachiDict は Apache-2.0 で継承条件がないため同梱してよい。README に出典と license を明記する。JMdict と KANJIDIC2 は CC BY-SA なので同梱しない。**市販教科書と日本語能力試験の過去問は取り込まない**——難易度の段階は語の頻度から自作し、「日本語能力試験の水準におおよそ対応」という表現に留める。
