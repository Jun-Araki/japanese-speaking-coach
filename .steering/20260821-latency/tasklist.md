## design.md からの変更点（**着手前に書く**）

design.md は **2026-08-21 に書かれ、その後 `68f15f3`「Listen without a button」で
連続リッスン（`app/continuous.py`）が入った。** 設計の 2 箇所がそれと噛み合わない。

### 変更1：**案 A（音声を入力欄より後ろに描く）は、連続リッスンでは音声が一度も鳴らない**

design.md §5 は `render_input()` の**後ろ**で `speak(answer)` を呼ぶ形を指定している。
しかし `render_input()` は連続リッスンのとき **`continuous.listen()` の `while True` の中で止まる**。

- 学習者が話し終えるまで戻らず、戻った直後に `_send_recording()` が `st.rerun()` する
- したがって **`render_input()` より後ろの行は、マイクが繋がった実行では一度も走らない**
- **音声が鳴るのは「ストリームが繋がらなかったターンだけ」になる。** 失敗時にだけ鳴る機能である

`CONTINUOUS_VOICE` の既定は `1` なので、これは例外経路ではなく**既定の経路**である。
**案 A をそのまま実装すると、9/13 の会場で音が出ない。**

**なお同じ理由で、「End the conversation」ボタンも `render_input()` の後ろにある**（`app/main.py`）。
マイクが回っている実行では描画されず、画面には**前回の実行で描かれた stale なボタンが残っている**。
押せば動くので破綻はしていないが、**B1 で順序を触るときに一緒に見る。**

→ **B1 で解く。3案を並べ、推奨を A-1 とする（下記）。**

### 変更2：`retrieval/index.py` の RLock は、design.md の書きぶりのままでは足りない

design.md §2 は「`_model()` と `collection()` を `RLock` で囲う」と書いているが、
**現在のコードには既に `_BUILDING = Lock()` が入っている**（2026-08-21、コンテナの health check が
「Collection [grammar] already exists」を出したため）。ただし**位置が `collection()` の本体の中**であり、

- `lru_cache` のキャッシュ判定は**ロックの外**で起きる
- 2 番目のスレッドはロックを待ったあと**本体をもう一度実行する**（`get_or_create` と
  `store.count()` が救っているだけ）
- **`_model()` には何も掛かっていない。** 5 スレッドが同時に初めて `search()` を呼ぶと
  **SentenceTransformer を 5 回読む**（手元で 8.55s × 5、Cloud のメモリでは落ちる）

→ **design.md の「キャッシュ付き関数を、ロックを取る素の関数で包む」形を採る。**
包む形にして初めて、2 番目のスレッドは**ロックの内側でキャッシュに当たる**。
`_BUILDING` は `_INIT_LOCK: Final = threading.RLock()` に置き換え、`_model()` と `collection()` の
**両方**で使う（`collection()` → `embed_passages()` → `_model()` と同じスレッドが二度取るので、
**`Lock` だと確実にデッドロックする**）。

### 変更3：訂正のバッチは `app/main.py` ではなく `app/corrections.py` に置いた（8/22 実装時）

A1 は `app/main.py` と書いていたが、**テストから import できないと B4 のテストが書けない。**
`app/main.py` は import しただけで画面のディスパッチまで走る（bare mode で動きはするが、
`st.session_state` に触る行がテストの前提になる）。

`app/limits.py` に前例があるとおり、**app 層の部品は Streamlit に依存しない別ファイルに置く**。
`app/corrections.py`（`streamlit` を import しない）に `correct_all` を置き、
`app/main.py` はそれを spinner で包んで呼ぶだけにした。
`tests/test_corrections_batch.py` は `app.corrections` を import する。

### 変更4：**音声を「この run で返答を作ったか」で判断してはいけない**（B1 実装時に実測で判明）

案 A-1 のとおり並べ替えたあと、**ブラウザで実際に動かしたら音声が一度も鳴らなかった。**
一時ログを仕込んで確認した結果がこれである。

```
TRACE run start
TRACE before speak, answer= True     ← 返答はできた
                                     ← 「after speak」が無い＝この run はここで捨てられた
TRACE run start
TRACE before speak, answer= False    ← 次の run から見ると返答は既に history にあり、話す物が無い
TRACE after speak 0.0
```

**マイクのウィジェットは自分で rerun を起こす**（接続状態が変わるたび）。
その rerun が**合成の 4.3 秒の最中**に来ると、音声を作っていた run ごと捨てられ、
次の run は「返答は既にある」ので何もしない。**結果として音声は永久に鳴らない。**

→ **`speak()` を呼ぶ条件を、run の流れではなく会話の状態から決める。**
`st.session_state["spoken"]` に**読み上げ済みの発話の位置**を持ち、
「最後が partner の発話で、まだ読み上げていない」なら読む。
`awaiting_reply` が返答の失敗を次の run で取り返すのと**同じ形**である。

- 印を付けるのは `speak()` の**後**（途中で捨てられた run は未読のまま残す＝次の run がやり直す）
- `start_session()` で `spoken = 0` を置く——**開始の挨拶は読み上げない**（現状の挙動を変えない）
- `SESSION_KEYS` に `spoken` を追加（会話終了で消える）

**修正後、ブラウザで音声要素（177KB の data URI）が最後の吹き出しの中に出ることを確認した。**

## 監査（2026-08-22、実装後）

**独立したサブエージェント監査は走らなかった**——3 本ともセッション上限で異常終了し、所見はゼロ。
**上限が戻ったら独立監査を回すこと。** 以下は自分で読み直した結果であり、
**同じ人間が書いて同じ人間が見ているので、独立監査の代わりにはならない。**

### 見つけて直したもの

**1.（重大）エコー捨てが、エコーではなく「過去の音声」を捨てていた。**
`streamlit_webrtc` の受信側は `maxsize=256` の FIFO キューで、満杯になると**古いフレームを捨てる**
（`receive.py:90-98`）。`collect_turn` に入る時点で、キューには
**文字起こし・返答・合成に使った数秒ぶんの「過去の」音声が詰まっている。**

- したがって `skip_seconds` ぶん読み捨てても、捨てているのは**キューの先頭＝過去の音**であり、
  **エコーは丸ごと検出器に届く**
- しかも過去の音には**学習者の前の発話の末尾**が入っており、
  **それが検出器の較正（最初の 0.5 秒）に入ると、雑音の下限が学習者の声より上に行く**
- **テストが通っていたのは、偽の受信側にバックログという概念が無かったから。**
  実装を読んで気づいた。**テストが設計の誤りを追認していた**

→ **先にキューを空にしてから `skip_seconds` を捨てる。** `get_frames` は
「バックログがあれば全部、無ければ 1 フレーム待って返す」ので、
**「1 件だけ返ってきた＝現在時刻に追いついた」**が停止条件になる。
バーストする受信側でも止まるよう `BACKLOG_LIMIT`（キュー 1 杯ぶん）で頭打ちにした。
`tests/test_continuous.py` は**本物のキューの振る舞いを模した偽物に書き直した**（6 件）。

**代償：** 返答の文字を読んで、音声が鳴る前に答え始めた学習者は、その出だしを落とす。
入力欄を先に描いたのと同じ取引である。

**2.（軽微）`graph()` が 5 スレッドから同時に呼ばれてグラフを 5 回コンパイルしうる。**
A1 で訂正が並列になって初めて起きるようになった、**A2 と同じ種類の競合**。
壊れはしない（各自が動くグラフを得るだけ）が、学習者が spinner を見ている 1 回で
