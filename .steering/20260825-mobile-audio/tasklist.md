# 携帯で「毎回マイク許可」「音が鳴らない」を直す（2026-08-25）

**requirements.md と design.md は作っていない。** 計画した変更ではなく、Jun が実機で踏んだ不具合の修正で、
原因の特定がそのまま設計だったため。**必要なら後から起こす。**

## 報告された症状（Jun / 携帯）

1. 話し終えるたびに **would like to access the microphone** が出る
2. **音声が鳴らない**

**どちらも PC では起きない。** そこが手がかりだった。

## 分かったこと

### (1) マイク許可 — Streamlit がコンポーネントを毎ターン作り直していた

**Streamlit は、あるコンポーネントより前に描かれる要素が変わると、その iframe を作り直す。**
会話画面は毎ターン発話が増えるので、マイクを会話の下（`render_input` の中）で開いていた構成では
**毎ターン新しい document になり、`getUserMedia` が呼び直されていた。**

- **PC**：許可をサイト単位で覚えているので、呼び直されても無言で通る → **誰も気づかない**
- **iOS Safari**：覚えないので **毎回ダイアログが出る** → Jun が見たもの

**測り方**：コンポーネントの `contentWindow` に印を付け、1ターン挟んで読み返した。

| 置き場所 | 結果 |
|---|---|
| 会話の**下**（従来） | 実アプリで**毎ターン消えた**（DOM ノードごと別物） |
| 会話の**上**（今回） | 実アプリで**2ターン連続で残った**／最小再現アプリで3ターン連続 |

**外れた仮説も書いておく**——最初は「要素の挿入」「`st.chat_input`」「返信生成の待ち時間」を疑って
順に潰した。**どれも単独では再現しなかった**（`st.chat_input` は交絡していただけで無関係）。

**対策**：`continuous.open_stream()` を `render_conversation()` の先頭、会話ループより前に移した。
**見た目の代償は無い**——`desired_playing_state` を渡してあるので開始/停止ボタンは描かれず、
機種選択は 8/24 に外し、送信専用なので映像も無い。**画面上は 16px の空白**である。

### (2) 音が鳴らない — iOS は「タップの最中」に頼まれた音声しか鳴らさない

読み上げ用の `st.iframe` も**毎リラン作り直される**（`srcdoc` が変わるため）。
**生まれたばかりの document は「タップされたことが無い」ので、iOS Safari は `speechSynthesis` を無視する。**
PC のブラウザはこの制限が無いので、ここでも PC だけ動いていた。

**対策は3つ**。

- **読み上げをページ本体から行う**——`window.parent.speechSynthesis` を使う。
  親ページはリランで作り直されず、学習者に何度もタップされており、音声一覧も読み込み済み
- **最初のタップで解錠する**——開始画面に1pxの枠を置き、**最初の `pointerdown`（＝Start を押す指）**に
  無音の発話を1つ乗せる。これが「タップ中に頼まれた」1回になる
- **黙ったら黙ったと言う**——900ms 待って始まらなければ ▶ の横に「← 押すと聞こえます」を出す。
  **失敗が無音と区別できないのが一番まずい**
