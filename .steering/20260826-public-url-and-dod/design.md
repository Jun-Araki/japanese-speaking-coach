## 1. 公開 URL の復旧

### 何が起きているか

**Streamlit Community Cloud は、git の更新を拾ってもプロセスを作り直していない。**
`app/main.py` は 8/25 のコードなのに、`sys.modules` の `app.theme` は 8/25 より前のもので、
新しい定数（`VOICE_SOURCE_NOTE` / `PROVIDER_VOICE_NOTE`）が無い。

**同じ壊れ方をローカルでも見た**（`localhost:8501` が古い `app.limits` を抱えて
`start_tts_cooldown` を見つけられなかった）。**環境の問題ではなく、
「動いているプロセスに新しいファイルを流し込む」という更新の仕方の問題**である。

### 手順（**上から順に。1つ試すごとに URL を開く**）

1. **Manage app → Reboot app。** これで直るなら原因は上記で確定
2. 直らなければ **Manage app のログを読む。** 赤い画面のメッセージは伏せられており、
   **本当のエラー名はログにしかない**
3. ログが依存の解決で落ちているなら、**`requirements-no-retrieval.txt` に差し替える判断**をする
   （PLAN.md が最初から用意している逃げ道。torch が Python 3.14 に載らない場合）
   — **その場合は README に「公開版は根拠の引用を出さない」と書く。**
     `correction.check_with_retrieval` は黙って劣化するが、**黙って劣化したことは書く**

### 直ったことの確かめ方（**「開いた」で終わらせない**）

- 開始画面が出る（注意書き・音声の1行・連絡先が見える）
- **場面とレベルを選んで1往復**。返答が日本語で返り、レベルが選んだものに見合っている
- 「会話を終える」で振り返りが出る（**訂正が並列で走る経路が本番で動くのはここが初めて**）
- **携帯で1回開く**（9/13 に人が触るのは携帯である）

## 2. 再発防止

**書く場所は `docs/{ja,en}/architecture.md`。** 専用の runbook は作らない——
**デプロイの話はすでにこのファイルにあり、置き場を増やすと片方が古くなる**（CLAUDE.md の2言語ルールと同じ理由）。

書くのは次の3行だけにする。**長い手順書は読まれない。**

- **push だけでは古いモジュールが残る。** 別ファイルに定数や関数を足して import した変更のあとは、**必ず再起動する**
- **再起動したら URL を開いて1往復する。** 「デプロイが成功した」は「アプリが動いている」ではない
- **赤い画面のメッセージは伏せられている。** 原因は Manage app のログにしかない

> **テストでは防げない、ということも書く。** `tests/test_screens.py` は
> **`app/main.py` を丸ごと実行する**ので、import の食い違いはローカルで確実に落ちる。
> **落ちなかったのは、ローカルのファイルが全部新しかったからである。**
> **本番で古いのはファイルではなくメモリ**であり、そこにテストは届かない。

## 3. README の仕上げ

### スクリーンショット（**英語注釈つき1枚**、DoD 項目）

**撮るのはローカルの画面にする。** 本番の画面はアクセスコードや URL が写り、
**撮り直すたびに本番を触ることになる。**

**注釈の入れ方を3案並べる。**

| 案 | 作り方 | 代償 |
|---|---|---|
| **A（推奨）** | スクショを撮り、**画像と注釈を並べた HTML を書いてブラウザで1枚に撮る** | 依存ゼロ。文字が画像に焼かれるので後から直すには撮り直す |
| B | Pillow を足して画像に描き込む | **依存が1つ増える。** 見た目の調整のたびにコードを書く |
| C | 画像は素のまま、注釈は README のキャプションに書く | **DoD の「英語注釈つき」を満たさない**（画像だけ切り取られたときに何も伝わらない） |

**A を採る。** 注釈は3つまでにする——**訂正が会話中に出ないこと・振り返りで理由が英語で出ること・
根拠の条番号が出ること。** この3つが「薄いラッパーではない」の見えるところである。

置き場は **`docs/images/`**（CLAUDE.md の規約）、形式は **PNG**。

### アーキ図

**新しく描かない。** README の 339 行目に mermaid の図が既にあり、GitHub はこれを描画する。
**DoD の「簡易アーキ図」はこれで満たしていると判断する**——
**図を2枚持つと、片方が必ず古くなる。**

### 公開 URL のリンク

**README の先頭に置く。** ただし**アクセスコードの扱いが付いてくる**ので、要求書の未決事項として
Jun の判断を待つ。決まるまで README には**書かない**（リンクだけ先に置いて、押した先で
コードを求められるのが一番悪い）。

**`interview-stories/` に置く**（`.gitignore` 済み ＝ 公開されない）。

## 6. 未実装の2機能（**判断が要る**）

| 機能 | 実装する場合 | 降ろす場合 |
|---|---|---|
| **「もう一度」ボタン**（書き起こしを取り消して言い直す） | **連続リッスンの再開に手が入る。** 8/22 に苦労した順序（入力欄 → 音声 → 回収）を触る | ドキュメントの記述と**画面遷移図の矢印**を消す |
| **AI の返事の文字を隠す切り替え** | 0.25h 程度。だが**聞き取り練習は DoD の外**である | 同上 |

**推奨は「両方降ろす」。** 理由は2つ。

- **9/6 と 9/13 の前に、動いている音声の経路へ手を入れる価値が無い。**
  「もう一度」は**壊れたら会話そのものが止まる場所**にある
- **どちらも「あると良い」であって、README が約束していない。**
  DoD にも無い

**降ろすなら、ドキュメントから消すだけにせず「作らないと決めた」と書く**——
消すと、**半年後に同じことを思いついて同じ議論をやり直す。**

## 8. リスク

- **再起動で直らない場合**（依存の解決で落ちている）。→ `requirements-no-retrieval.txt` へ切り替え、
  **公開版が根拠を出さないことを README に書く**。**1h の見積は超える**
- **実機確認 (b) が通らない場合**（自分の声でターンが終わる）。→ 緩衝の 3h を使う。
  **それでも直らなければ `CONTINUOUS_VOICE=0` で押して話す形に戻す**——
  9/13 は「押さずに」より「音声で練習できる」が上位である
- **スクショが撮れない場合**（画面が本番と違う）。→ ローカルで撮ると決めているので、
  **本番との差が出るのは公開 URL のアクセスコードだけ**である
