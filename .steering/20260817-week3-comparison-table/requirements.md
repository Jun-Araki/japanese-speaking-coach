## 1. 今回やること

**素朴なベースラインと本実装を並べた表を、`dev` 80件で出す。** ただし RAG はまだ無いので、
**RAG を含む段（①）だけを欠いた形**で出す。

これは新しい機能の追加ではない。**すでにあるものを測って並べるだけ**である。
`correction/baseline.py`（`baseline-v1`）と `correction/engine.py`（`correction-v1`）は両方とも動き、
検証①③は `correction/validation.py` に実装済みで、採点は `evals/score.py` が持っている。

## 2. なぜ今週これなのか

**9/20 が全体の最低ラインで、その中身が「比較表がある／改善サイクルが1周回っている」だからである。**
ここが出ていれば以降どこで遅れても価値はゼロにならないし、逆にここを落とすと
10月以降に何を作っても「作っただけ」になる。**5週あるうちの1週目を、表の骨格に充てる。**

**RAG を待たない理由**：RAG は3〜4週かかる見込みで、待つと表そのものが9月半ばまで存在しない。
**先に骨格を出し、①列だけ後から足す**ほうが、途中で計画が崩れたときに残るものが多い。

## 3. 測る段

**「段」の番号と「検証」の番号は別物である。** 混同すると表が読めなくなるので先に固定する。

| 段 | 中身 | 追加の API 呼び出し |
|---|---|---|
| **ベース** | 素朴な1回呼び出し（`baseline-v1`） | **不要**（測定済み。`dev` は 98.4% / 64.7%） |
| **⓪** | **本実装プロンプト**（`correction-v1`）・RAG なし・検証なし | **1回だけ必要**（80件） |
| **②** | ⓪ ＋ **検証①（書き換えすぎの検出）** | **ゼロ**（⓪の出力への後処理） |
| **③** | ⓪ ＋ **検証③（余計な直しの抑制）** | **ゼロ**（同上） |
| ~~①~~ | ~~＋RAG・検証なし~~ | **今週は出さない**（RAG 未着手） |

**検証②（レベル超過による再生成）はこの表に載らない。** `dialogue.reply()` の中で起きるもので、
評価スクリプトは `correction.check()` しか呼ばないため、訂正側の記録に置くと構造上つねに 0 になる。
**検証②は 90返答の測定記録（`level_compliance`）が持っている**（測定済み：1発目 94.4% / 再生成後 98.9%）。

**旧計画は②③を「①の出力への後処理」と書いていた。** ①が無いので**⓪の出力に当てる**。
この差は表に明記する——後から①を足したとき、②③の値は動く。

## 4. ユーザーストーリー

1. **面接官として**、素朴な実装とこの実装が同じデータで並んでいるのを見られるので、
   **「大規模言語モデルに投げただけではないか」という疑いに、数字1つで答えてもらえる。**
2. **面接官として**、各段が「プロンプトの差」と「検証ノードの差」に分かれているのを見られるので、
   **どの工夫がどれだけ効いたのかが分かる**（合計の差だけでは、何が効いたのか言えない）。
3. **開発者として**、一番低い指標がどれか分かるので、**翌週以降の改善サイクルで何を1つ選ぶかを決められる。**
4. **開発者として**、`dev` で測ったと明記されるので、**調整に使った側の数字であることを自分で誤解しない。**

## 7. 今週わかっていること — 検証③は公平に測れない

**先に書いておく。結果を見てから言い訳にしないため。**

検証③（余計な直しの抑制）の規則は「**根拠が引けておらず、かつ元の文が十分自然なら『直す必要なし』に倒す**」である。
**RAG が無い今週、「根拠が引けていない」は全件で真になる。** つまり判別を担うのは丁寧さの述語だけになる。

そして**採用基準は事前登録されている**：「`dev` で `false` 側の発火率が `true` 側より **20pt 以上**高いこと」。
2026-08-10 の実測では、場面の段階を見る版で **93.3% 対 81.1% ＝ +12.2pt** だった。**20pt に届いていない。**

したがって**今週の③は、検証③の採否を決める測定にはならない。**

- **今週の③は「根拠が常に空のときにどう振る舞うか」を見る数字**であって、それ以上ではない
- **採否の判定は、RAG が入って「根拠が空」が本当に判別として働くようになってから**（8/31〜9/6 以降）
- **この但し書きを表に書く。** 書かずに③を載せると、読む側は採否の根拠だと受け取る

**これは失敗ではなく順序の問題である。** ただし「測ったが判定には使えない」と
**自分から書けるかどうか**が、この表の信頼性を決める。
